# Why a dependency's age alone is not the supply defence

One rule, supply.age.1, rests on the reason below. It keeps its status.

- **supply.age.1** (Hard, active): In the xz backdoor, version 5.6.0 was 33 days old and 5.6.1 was 19 days old at discovery, so a two-week window would have admitted both. The other supply rules (provenance, licence, scans, install scripts) do the work the window cannot. In the web estate an install that followed the lock passed a young locked entry, and one repository set the window to one day.

arch.decisions.1, arch.decisions.4, docs.links.2
